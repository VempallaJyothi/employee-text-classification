# Employee Text Classification (POC)

A small full-stack proof of concept that classifies employee-related text (skills or descriptions) into a category using a locally trained **fastText** model.

A user types text in a React page. The React app sends it to a FastAPI backend. The backend runs a fastText classifier and returns the predicted category and a confidence score as JSON.

**Example**

Input: `I am a Java developer with Spring Boot experience.`

Output:

```json
{
  "text": "I am a Java developer with Spring Boot experience.",
  "category": "Java Backend",
  "confidence": 1.0
}
```

## Technologies

| Layer | Technology |
|---|---|
| Frontend | React + Vite (JavaScript, `fetch()`) |
| Backend | Python 3.11 + FastAPI + Uvicorn |
| NLP / classification | fastText (`fasttext-wheel`) |
| API testing | Postman |
| OS used for development | Windows |

## Features

- Classifies text into 5 categories: Frontend, Java Backend, Python Backend, DevOps, Data
- Returns a confidence score for every prediction
- Input validation (empty text, oversized text, invalid JSON)
- CORS enabled for the React development server
- Loading state and clear error messages in the UI
- Model trained locally on a small dataset: no external APIs and no large downloads
- Interactive API docs at `/docs` (generated by FastAPI)

## Architecture

```
React Frontend (http://localhost:5173)
        |  POST /predict  (JSON)
        v
FastAPI REST API (http://127.0.0.1:8000)
        |
        v
fastText classification model (model/employee_classifier.bin)
        |
        v
Prediction + confidence
        |
        v
JSON response  ->  React displays the result
```

## Installation

Prerequisites: Python 3.11, Node.js 20.19+ (or 22.12+), npm.

### Backend (Windows, Command Prompt)

```bat
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

If you are starting from scratch instead of using `requirements.txt`:

```bat
pip install fastapi "uvicorn[standard]" fasttext-wheel "numpy<2"
```

NumPy is pinned below 2 because fastText's `predict()` fails with NumPy 2.x.

### Train the model

```bat
python train_model.py
```

This reads `data/train.txt` and writes `model/employee_classifier.bin`.

### Frontend

```bat
cd frontend
npm install
```

## Running the project

Use two terminals.

**Terminal 1: backend**

```bat
cd backend
venv\Scripts\activate
uvicorn main:app
```

The API runs at `http://127.0.0.1:8000`.

**Terminal 2: frontend**

```bat
cd frontend
npm run dev
```

Open `http://localhost:5173/`.

## API endpoints

### `GET /`

Health check.

```json
{ "message": "Employee Text Classification API is running" }
```

### `POST /predict`

Headers: `Content-Type: application/json`

Request:

```json
{ "text": "Experienced in React, JavaScript and CSS." }
```

Response (`200 OK`):

```json
{
  "text": "Experienced in React, JavaScript and CSS.",
  "category": "Frontend",
  "confidence": 1.0
}
```

Error responses:

| Status | When |
|---|---|
| 422 | Empty or whitespace-only text, missing `text` field, invalid JSON, text longer than 1000 characters |
| 400 | Text contains no usable words (for example `"!!!"`) |

Interactive docs: `http://127.0.0.1:8000/docs`

## How the model works

- `data/train.txt` has one example per line: `__label__<category> <text>`.
- fastText turns words (and word pairs) into vectors, averages them per sentence, and learns to map that average to a label.
- The trained model is saved as a `.bin` file containing the vocabulary, learned vectors, and classifier weights.
- At prediction time, the input is lowercased and stripped of punctuation (matching the training data), and fastText returns the best label with a softmax probability, which is the confidence score.

## Limitations

- The training set is small (100 examples) and hand-written, so results on real-world text will vary.
- The reported accuracy is measured on the training data and is not a real evaluation.
- fastText always picks one of the 5 labels, even for unrelated text. A low confidence is the only hint.
- Confidence is the model's certainty, not a guarantee of correctness.

## Future improvements

- Larger, real-world training data and a separate test set for honest accuracy metrics
- An "Unknown" category or a confidence threshold for unrelated text
- Return the top 3 predictions with their confidences
- Multi-label prediction (a person can be both Frontend and Data)
- Automated tests for the API (pytest) and the UI
- A retraining endpoint or script driven by new labelled data
- Deployment configuration (Docker, cloud hosting) and authentication for production use
